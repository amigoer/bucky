# Bucky 需求与开发规范

## 文档关系与当前范围

Bucky 是开源、免费、全平台、AI 原生的对象存储桌面客户端。项目名为 Bucky，仓库为 `amigoer/bucky`，CLI 命令为 `bucky`。

**当前决定：v0.1 接入腾讯云 COS、阿里云 OSS、AWS S3 和 Cloudflare R2 四种类型，其他服务后续按类型逐个接入。** 本仓库仍处于文档规划阶段，尚未开始工程实现。

## 开发方式

开始实现时，先阅读本规范、开发架构、开发规划和 ADR。只执行当次明确选择的阶段，先给出任务清单与验收标准，经确认后写代码；每阶段结束更新实现状态、验证结果与下一步。

首个代码阶段是「Phase 0：工程脚手架」。创建根目录开发约定并验证桌面入口、原生视图渲染和任务命令，不直接跨到全部存储与功能实现。

## 工作规则

1. 不确定第三方 API 时，阅读官方文档或源码；依赖锁定具体版本，按当前阶段需要引入。
2. 全部使用纯 Go；桌面界面由 MyGo 原生工具包绘制，不引入 WebView；CLI 与桌面端都支持 `CGO_ENABLED=0` 构建。
3. 业务用例写有意义的单元测试；S3 协议运行 MinIO/RustFS 契约测试，每种已接入类型都完成真实服务验证。禁止在仓库、输出或日志中写真实密钥。
4. 使用 Conventional Commits 小步提交。重要决策写 ADR，记录背景、决策、备选方案与后果。
5. 删除、移动、覆盖等操作必须先出计划，再经确认执行。只读限制统一在业务用例层执行。
6. 设计采用自己的界面、文案与图标，不复刻竞品。未确定的产品范围先说明建议，不自行扩大。
7. 每阶段运行当前已有的 lint、类型检查和测试；记录未验证项，不把目标写成实测结果。
8. 源代码、标识符、注释和提交信息使用英文；用户文档沿用各自语言。

## 产品定位

目标用户包括管理 COS/OSS/S3/R2 的开发者、用对象存储做图床的内容作者，以及通过 CLI/MCP 操作存储的 agent 用户。跨云迁移团队在多个存储类型稳定后再覆盖。

产品方向：

- macOS、Windows、Linux 上统一的桌面体验，开源免费。
- 本地优先，凭证留在系统钥匙串，默认无遥测。
- 国内外存储逐类接入，按实际能力展示功能。
- GUI、CLI、MCP 复用连接和业务规则，Agent Skill 引导先定位、预览，再执行。
- 后续提供跨云同步、安全体检和磁盘挂载，不把未来功能作为首版前置依赖。

## 技术栈

具体版本以 ADR-001 为基线，实施时核实并精确锁定。

| 层 | 选型与边界 |
| --- | --- |
| 后端 | Go，单一 module `github.com/amigoer/bucky` |
| 桌面 | MyGo（`github.com/egoist/mygo`）原生 UI 工具包，伪版本锁定到具体提交；仅 `cmd/bucky-desktop` 与 `internal/desktop` 依赖它 |
| 桌面界面 | Go 视图（`ui` 包）直接调用 `service`，无绑定、无 IPC、无前端构建；图标取自 Lucide（ISC），中英文案随二进制嵌入 |
| R2 / S3 | AWS SDK for Go v2 `service/s3`；协议差异集中在适配器和类型配置 |
| COS / OSS | 腾讯云 `cos-go-sdk-v5`、阿里云 `alibabacloud-oss-go-sdk-v2` 原生适配器，基础读写也走原生 SDK；版本在各自接入阶段核实并锁定 |
| 凭证与数据 | 系统钥匙串 + SQLite（modernc.org/sqlite），不在 SQLite 存密钥 |
| CLI / MCP | Cobra、官方 MCP Go SDK，复用同一应用服务 |
| 测试 | Go testing、testify、testcontainers-go；MinIO/RustFS 和显式真实云验证 |
| 构建与质量 | Taskfile、`go tool mygo build`、golangci-lint、GitHub Actions 三平台检查 |

## 架构约束

架构为「入口适配 → 应用服务 → 核心契约 → 存储适配」，模块和数据流见开发架构。

- 一个本地核心，不引入业务服务器、微服务或运行时插件系统。各入口独立启动，共用配置和 SQLite，写任务通过进程锁避免竞争。
- `service` 处理连接、浏览、传输编排、只读与执行计划；`app`、CLI 和 MCP 只转换输入输出。
- `core` 的中立模型不暴露云 SDK、桌面框架或数据库类型；`drivers` 处理厂商 API、签名、分页和错误差异。
- 基础读写使用小接口；桶发现、分片、预签名和复制等为可选能力。声明能力不代表当前凭证一定有权限。
- 长任务可取消、可查询状态；传输与执行计划持久化，重启后先核对状态再恢复；统计缓存可失效重算。
- 未来适配器按实际阶段创建，不在首版加入空驱动、未使用 SDK 或未验证的连接入口。

## 存储类型与支持范围

| 类型 | 版本 | 边界 |
| --- | --- | --- |
| 腾讯云 COS | v0.1 | 原生 SDK，已有桶内的对象管理；支持指定桶名（带 APPID 后缀）和只授权单桶的子账号凭证 |
| 阿里云 OSS | v0.1 | 原生 SDK，已有桶内的对象管理；支持指定桶名和 RAM 用户凭证；CDN/图片处理后续按能力开放 |
| AWS S3 | v0.1 | S3 协议实现，覆盖普通桶、Region 与明确的凭证来源 |
| Cloudflare R2 | v0.1 | 与 AWS S3 共用 S3 协议实现；支持指定桶名、桶级凭证和可选的 Cloudflare 登录 |
| 通用 S3 兼容服务 | 后续 | 自定义 endpoint、path-style 和经验证的 MinIO/RustFS/B2/Wasabi/Spaces 等预设 |
| 七牛 Kodo | 后续 | 逐类型接入，原生功能分别验收 |
| Azure Blob / Google Cloud Storage 等 | 后续 | 非 S3 协议，新增独立适配器 |

MinIO 和 RustFS 在 v0.1 仅作为 S3 协议测试后端，不代表已提供这些连接类型。COS 和 OSS 走原生 SDK，不能用 MinIO/RustFS 代替验证。“兼容 S3”不能替代每家服务的真实验证。

## v0.1：功能范围与验收

首版完成下表，四种类型都按同一套标准验收；类型之间能力不同的地方按实际能力展示，不为某一家单独改流程。通用 S3 兼容服务、其他厂商、跨连接复制、跨云同步、桶创建/删除、云账号管理、AWS profiles 导入、自动更新和挂载均不纳入首版。

| 模块 | 必须做到 | 验收标准 |
| --- | --- | --- |
| 连接 | 四种类型各自的密钥与地域、指定桶名、测试连接、多配置切换、只读连接、系统钥匙串；R2 可选浏览器 Cloudflare 登录 | 只授权单个桶、没有列桶权限的凭证仍能使用指定桶；错误权限有准确提示；密钥不出现在界面状态或数据库；Cloudflare 登录铸出的单桶令牌可撤销 |
| 浏览 | 桶发现或指定桶、prefix 文件夹、面包屑、列表/网格、分页、排序、搜索、元数据 | 10 万对象数据集的分页与虚拟滚动不阻塞界面；区分已加载筛选和全 prefix 搜索/排序 |
| 预览 | 图片、文本/代码/JSON 在窗口内绘制；视频、音频、PDF 显示元数据并可下载或按预签名链接在浏览器打开；文本有大小上限 | 大视频不必完整下载；超限有提示；各平台降级行为已记录 |
| 对象操作 | 文件/目录拖拽上传、下载、文件夹标记、复制、重命名/移动、批量删除 | 同一连接内操作；复制后才删源；覆盖/移动/删除先预览并确认；批量部分失败可查询 |
| 传输 | 并发、分片、暂停/继续/取消/重试、断点续传、进度、速度、剩余时间、限速和校验 | 5 GB 文件断网/终止进程后能恢复，重新下载哈希一致；源文件变化会阻止错误续传 |
| 分享 | 临时链接、已配置公开域名链接，一键复制 | 临时链接默认 1 小时，各类型的最长有效期按官方限制核实后再展示；预签名链接和自定义公开域名分开处理；目录返回链接清单 |
| 用量 | 按 prefix、文件类型后台统计数量与大小，缓存并显示时间和范围 | 可取消、不阻塞界面，不将部分扫描冒充全量统计 |
| 图床 | 剪贴板快捷上传、路径模板、可选压缩/WebP、复制 Markdown 链接 | 正常网络下小图目标 3 秒，记录实测环境；临时链接明确到期时间 |
| Agent | CLI、MCP、Agent Skill，复用同一套连接和用例 | 下面两条场景通过；只读、确认和错误行为与 GUI 一致 |
| 基础体验 | 中英双语、明暗主题、快捷键、完整的加载/空/错误状态 | 两种语言与主题逐页走查，三平台主流程通过 |

各类型的连接字段：COS 为 SecretId / SecretKey 与地域（如 `ap-guangzhou`），桶名带 APPID 后缀；OSS 为 AccessKey ID / Secret 与地域 endpoint（如 `oss-cn-hangzhou`），可选内网 endpoint；AWS S3 为 Access Key ID / Secret 与 Region，自定义 endpoint 和 path-style 属于后续的通用 S3 兼容服务；R2 见下段。四种类型都可以指定桶名、选择凭证来源（钥匙串或显式的进程环境）、配置公开访问域名和设为只读。

R2 region 使用 `auto`，endpoint 按账号和地域管辖配置。首版不要求手动填写 Cloudflare 管理 API token：可选的浏览器登录（OAuth + PKCE）会铸出一把仅限所选存储桶的 R2 令牌，手动 S3 密钥仍是默认后备。两者都不修改桶权限或 CORS。生成预签名是本地签名，不等同连接/权限验证。详细限制与官方资料见开发架构与 ADR-0003。

## CLI、MCP 与 Agent Skill

CLI 命令名为 `bucky`。以只读命令先验证驱动，再实现写操作，最后开放 MCP 和 Skill。命令与工具的实际签名在相应阶段核实并记录，首版不能声明尚未实现的入口。

| CLI 能力 | 说明 |
| --- | --- |
| `profiles` | 添加、测试、列举连接；不输出密钥，不通过命令行参数接收密钥 |
| `ls`、`stat`、`find` | 浏览、元数据、按名称/时间/大小查找；说明扫描范围 |
| `cp` | 本地与对象存储互传、同一连接内复制；不支持跨连接 |
| `mv`、`rm` | 移动/删除，默认先生成计划 |
| `presign` | 单对象临时下载链接，默认 1 小时 |
| `du` | prefix 数量与大小统计 |
| `upload-image` | 图床上传并返回 Markdown 链接 |
| `mcp` | stdio MCP server |

所有命令支持稳定的 `--json` 结果和错误结构，实施时新增 `docs/cli-schema.md`。退出码：0 成功，1 一般错误，2 参数错误，3 部分失败，4 需要确认。

删除、移动、覆盖在非交互环境默认只出计划。CLI 显式确认参数或客户端确认后按 plan ID 执行；MCP 执行工具只接受已生成的 plan ID。计划绑定目标、对象状态和有效期，执行前重新检查只读和冲突。重复执行返回既有状态，不能并发执行同一计划。

plan ID 仅标识计划，不证明用户已确认。Phase 5 必须验证各客户端可由人控制的确认机制，记录其信任边界；不能可靠取得确认的客户端只开放读取和计划，不开放写执行。模型文字或 `confirmed: true` 参数不作为独立确认凭据。

MCP 提供连接列举、对象查询/读取、分享、用量、上传和计划/执行工具；注解按实施时的规范核实。Skill 教 agent 先定位、预览、展示计划、等待确认再执行；安装目录和客户端支持在 Phase 5 核实。这里不预设内置模型聊天或模型 SDK。

首版验收场景，四种类型分别验证：

1. agent 找到某个连接中 `backups/` 下 90 天前的对象，展示移动到同连接 `archive/` 的计划，确认后执行并汇报；拒绝确认不发写请求。
2. agent 上传目录 `dist/` 到某个连接，返回逐对象链接或链接清单，有效期取 7 天与该类型上限中较短的一个。目录本身不能当作单对象签名。

## 工程质量与发布门槛

| 维度 | 要求 |
| --- | --- |
| 性能 | 冷启动目标 2 秒内、空闲内存目标 150 MB 内；记录安装包体积、环境和实测值，不作无依据承诺 |
| 安全 | 默认无遥测；密钥仅钥匙串或显式的进程环境来源；日志脱敏；签名链接不落日志/缓存；只读和操作确认统一执行 |
| 可靠性 | 流式传输、状态恢复、明确超时与有限重试；ETag 不当作通用 MD5；移动不是原子操作，部分失败可追踪 |
| 测试 | 用例/状态/只读单元测试；MinIO 与 RustFS 的 S3 协议契约测试；COS、OSS、S3、R2 真实服务的权限、签名、校验、续传和预览验证 |
| 质量 | golangci-lint 与 `go test` 通过；`core`、`service`、`transfer` 覆盖率目标 70% 以上；关键传输有基准测试 |
| CI | 普通 PR 跑无云密钥的检查、本地协议集成与三平台构建；真实云验证显式运行，不给不可信 PR 提供凭证 |
| 数据 | 云测试使用独立测试桶/限定 prefix，不影响生产数据；按操作计划清理，并记录清理失败 |
| 界面 | 独立视觉语言，加载/空/错误状态完整；语言和主题均覆盖 |

## 后续方向与发布材料

版本接入顺序和阶段以开发规划为准。至少两种类型稳定后再规划跨云复制与同步；安全体检、自然语言操作、PicGo/编辑器生态、自动更新与包管理器分发后续单独排期。

v1.0 保留挂载本地磁盘的方向。到对应阶段评估现有 VFS、NFS/FUSE、Windows 驱动及系统文件提供接口，单独记录依赖、许可和平台限制。首版只保留流式读写与中立接口，不提前引入文件系统组件。

README 面向用户，英文默认并同步中文，区分“计划支持”与“已支持”，不介绍过多实现细节。发布前补实际截图、各类型的演示、安装说明、已知限制和实测性能；有发布产物后再展示下载按钮和 release 徽章。

发布准备完成后提交可审阅的安装包和说明。创建 Release、上传附件、部署网站和包注册表分发必须取得当次明确授权。文档或阶段验收通过不自动授权对外发布。

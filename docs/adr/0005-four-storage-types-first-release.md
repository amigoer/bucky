# ADR-005：v0.1 接入 COS、OSS、S3、R2 四种类型

- 状态：已采纳
- 日期：2026-10-20
- 相关：[ADR-001](0001-tech-stack.md)、[ADR-002](0002-r2-first-storage.md)、[ADR-003](0003-cloudflare-oauth-connection.md)、[SPEC](../SPEC.md)、[开发架构](../architecture.md)、[开发规划](../development-plan.md)

## 背景

ADR-002 把 v0.1 限定为 Cloudflare R2，AWS S3、阿里云 OSS、腾讯云 COS 依次放到 v0.2、v0.3、v0.5，目的是先在一个类型上验证完整流程。

Amigoer 重新确定了首个里程碑（M0，即 v0.1）的目标：Bucky 首版就是腾讯云 COS、阿里云 OSS、AWS S3 和 Cloudflare R2 的客户端。2026-10-20 的桌面设计稿按这四种连接类型设计，新增连接、侧栏和各页面都以四家并列为前提。

## 决策

### v0.1 可以创建四种连接类型

`cos`、`oss`、`s3`、`r2` 四种类型都可以在桌面端、CLI 和 MCP 中创建和使用。SPEC 的 v0.1 功能表对四种类型同样适用：连接、浏览、预览、对象操作、传输、分享、用量、图床、Agent 和基础体验都要在每种类型上通过验收。

### 适配方式沿用 ADR-002 的原则

| 类型 | 实现 |
| --- | --- |
| R2 | `s3compat`，配置 R2 endpoint、region `auto`、校验策略和能力 |
| AWS S3 | 复用 `s3compat`，增加 AWS Region、凭证来源和能力配置；只覆盖普通桶 |
| 阿里云 OSS | 原生适配器，使用 `alibabacloud-oss-go-sdk-v2`，基础读写也走原生 SDK |
| 腾讯云 COS | 原生适配器，使用 `cos-go-sdk-v5`，基础读写也走原生 SDK |

COS 与 OSS 一样走原生 SDK，不经由 S3 兼容接口，原因与 ADR-002 否决「所有云都强制走 S3」相同。两个 SDK 的版本以 ADR-001 的参考版本为起点，在各自接入阶段核实并锁定。

### 能力差异通过能力声明表达

预签名的最长有效期、存储类型名称、分片大小与数量限制、公开访问域名、服务端复制等差异，由各驱动的能力声明和配置给出，应用服务和界面按能力展示。具体限制以官方文档为准，在接入阶段核实后写入开发架构；没有核实的限制不写进界面文案。

### 验证要求

- MinIO 和 RustFS 仍只作为 S3 协议测试后端，只覆盖 `s3compat`。
- COS 和 OSS 目前没有选定的本地测试后端。驱动契约测试复用同一套用例，在显式提供凭证时对真实服务运行。
- 四种类型都要用真实服务完成权限、签名、校验、续传和预览验证，才能在发布说明中写成「已支持」。

### 不变的部分

- 浏览器 Cloudflare 登录（ADR-003）只用于 R2；COS、OSS、S3 在 v0.1 只支持手动填写密钥，凭证来源为系统钥匙串或显式的进程环境。
- 通用 S3 兼容服务（自定义 endpoint、path-style、各家预设）、七牛 Kodo、Azure Blob、Google Cloud Storage 仍放在后续版本，顺序以开发规划为准。
- OSS 与 COS 的 CDN 刷新、图片处理等原生增强不进入 v0.1。
- 跨连接复制、跨云同步、桶创建/删除、云账号管理、AWS profiles 导入继续排除在首版之外。

## 对已有决策的影响

- 替代 ADR-002 中「v0.1 只有 R2」一节和「v0.1 R2 → v0.2 AWS S3 → v0.3 OSS → v0.4 通用 S3 兼容服务 → v0.5 COS/Kodo」的接入顺序。ADR-002 的四层结构、业务类型与协议实现分开、小接口与显式注册、R2 配置边界继续有效。
- ADR-001 依赖表中 OSS（v0.3）、COS（v0.5）的版本标注不再适用，两个 SDK 改为 v0.1 依赖，仍在接入阶段核实版本。
- ADR-003 不变。
- 开发规划需要为 S3、OSS、COS 增加 v0.1 内的阶段；开发架构的存储类型表和 CLI 规格（`docs/cli-schema.md`）的连接与地址格式需要覆盖四种类型。这些文档另行更新。

## 备选方案

- **保持 R2 首版，按 ADR-002 的顺序接入**：先在一个类型上把流程做完整，风险最低，但首版不能满足 M0 「四家客户端」的目标。
- **COS 和 OSS 也走 S3 兼容接口**：两家都提供 S3 兼容访问，复用最多；但原生能力和错误表达受兼容层限制，ADR-002 已否决这一做法。
- **先开放通用 S3 兼容服务（自定义 endpoint）**：一次覆盖更多服务，但协议兼容不等于逐家验证，且仍覆盖不到 COS、OSS 的原生行为。

## 后果

- v0.1 工作量明显增加：新增 COS、OSS 两个原生驱动和 S3 的配置，四个真实账号与测试桶，首版发布时间相应推后。
- 分片续传要在 `s3compat`、OSS、COS 三个实现上分别对接 transfer 引擎的分片契约，并分别验证断点恢复。
- 能力差异必须先核实再展示；分享、用量等页面的提示文案按类型取值，不能统一写死。
- CLI 现有以 R2 为前提的命令说明、环境变量和地址格式需要随驱动一起调整。

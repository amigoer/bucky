## 1. 交付原则

第一版只接 Cloudflare R2。先把连接、浏览、传输、确认执行、预览、分享和 Agent 使用流程做完整，再按存储类型扩展。保留已确定的 Wails v3 + React 技术栈，所有入口复用同一组业务用例。

版本范围和实施阶段分开管理：v0.1 是 R2 版本，Phase 0–6 是它的实现顺序。阶段验收完成不代表已发布；后续版本的类型未实现时，不提供可点击的空入口，也不把测试后端宣传为支持的产品。

## 2. 按存储类型划分版本

| 版本 | 存储类型 | 接入重点 | 退出标准 |
| --- | --- | --- | --- |
| v0.1 | Cloudflare R2 | R2 S3 API、指定桶连接、可靠传输、桌面/CLI/MCP 共用流程 | 真实 R2 完成首版全部验收；三平台可安装 |
| v0.2 | AWS S3 | 复用 S3 协议实现；region、AWS 凭证来源、普通桶权限差异 | R2 无回归；AWS 普通桶完成契约与真实服务验证 |
| v0.3 | 阿里云 OSS | OSS 原生 SDK 适配基础读写、签名、分片和错误；再增量接 CDN/图片能力 | R2、S3 无回归；OSS 基础流程通过，增强能力单独记录支持范围 |
| v0.4 | 通用 S3 兼容存储 | 自定义 endpoint、path-style 等选项；分批验证 MinIO、RustFS、B2、Wasabi、Spaces | 每个发布的预设都有测试记录，不承诺任意 endpoint 完全兼容 |
| v0.5 | 腾讯云 COS、七牛 Kodo | 按类型接入并逐个验收，分别处理凭证、签名和原生功能 | 每种类型独立验证；一种未完成不影响另一种交付 |
| 后续 | Azure Blob、Google Cloud Storage 等 | 非 S3 协议适配，共用已有浏览与传输流程 | 一次一个类型，先完成契约测试再开放界面 |

v0.2、v0.3 优先完成新类型的基础对象操作，不同时建设完整云控制台。AWS S3 Express、Table/Vector bucket、IAM 管理和 OSS 账号管理均不自动纳入相应版本。

## 3. v0.1 的完整闭环

用户可以配置一个有桶级权限的 R2 连接，浏览已有桶和对象，拖拽上传目录，观察/恢复传输，预览文件，复制临时或公开链接，并在确认计划后批量移动或删除。CLI 与 MCP 复用同样的连接、只读规则和执行计划。

首版仍包含原定的图床、用量统计、中英双语和明暗主题；它们在 R2 核心操作稳定后实施，不扩展到其他厂商。上传下载恢复和确认机制是首版要求，不通过“架构简单”将可靠性工作省略。

明确不做：其他厂商连接、AWS profiles 导入、跨连接复制/同步、桶创建/删除、云账号与策略管理、CDN 配置管理、安全扫描、内置模型聊天、挂载磁盘、自动更新和包管理器分发。新增上述范围必须单独调整计划。

## 5. Phase 1：R2 连接与只读浏览

**目标：**CLI 先验证存储接入，同时建立可复用的领域与用例边界。

- [ ] 定义 `core` 模型、小接口、错误与能力，建立 `service`、`profile`、`store` 和驱动工厂。
- [ ] 实现 `r2` 类型配置，使用 `s3compat` 处理 endpoint、`auto` region、签名和校验策略。
- [ ] 实现凭证保存/读取、只读连接、指定桶连接；不强求桶列表权限。
- [ ] 实现桶发现、分页列举、元数据、有界文本读取和预签名。
- [ ] CLI 提供连接添加/测试/列举及 `ls`、`stat`、`find`、`presign`；交互录入密钥或使用环境凭证，不把密钥放在参数中。
- [ ] 增加 CLI JSON 输出文档和退出码约定；全量 prefix 搜索与已加载筛选分开标识。

**验收：**桶级只读凭证能够连接指定 R2 桶；无法列桶时仍可浏览；分页无漏项/重复；特殊字符 key、错误凭证、超时与权限错误正确呈现；预签名链接实际可读且过期后失效；MinIO/RustFS 契约测试通过并记录真实 R2 验证。

**交付：**可用的 R2 只读 CLI、真实服务验证记录、CLI 输出说明。

## 6. Phase 2：可靠传输与确认执行

**目标：**建立所有入口共用的上传、下载、复制、移动和删除流程。

- [ ] 实现流式上传下载、队列、并发上限、暂停/继续/取消/重试、进度与限速。
- [ ] 实现分片上传和 SQLite 状态保存，恢复前核对本地源文件及远端分片。
- [ ] 实现下载临时文件和恢复校验，避免把未完成下载当作最终文件。
- [ ] 实现执行计划、有效期、只读检查、覆盖确认、逐项结果及重复/并发执行保护。
- [ ] 实现同一连接内复制和移动；大对象使用分片复制；复制成功且核对后才删除源。
- [ ] 实现 CLI `cp`、`mv`、`rm`、`du`；`cp` 只支持本地与 R2、同一 R2 连接内部，不开放跨连接模式。
- [ ] 实现数据目录的进程写锁；GUI、CLI、MCP 不会同时恢复同一任务。

**验收：**5 GB 文件断网/终止进程后可恢复上传，重新下载哈希一致；改变源文件会阻止错误续传；取消能处理残留分片；无确认不能删除或覆盖；复制失败保留源对象；部分失败可逐项查询；只读连接在所有写用例中被拒绝。

**交付：**R2 完整读写 CLI、任务与计划持久化、故障恢复和操作确认测试。

## 7. Phase 3：桌面主流程

**目标：**在桌面完成 R2 日常管理，不复制 CLI 的业务逻辑。

- [ ] 接入 Wails 薄绑定和进度事件；React 按连接、浏览器、传输、设置组织功能。
- [ ] 完成连接新增/测试/编辑/删除、指定桶与只读标记；新增类型仅显示 R2。
- [ ] 完成面包屑、列表/网格、分页、搜索、元数据、加载/错误/空状态。
- [ ] 完成文件/目录拖拽上传、下载路径选择、传输面板及任务恢复入口。
- [ ] 完成计划预览、覆盖和批量删除确认、部分失败展示。
- [ ] 完成中英双语、明暗主题和核心快捷键。

**验收：**桌面完成连接 → 浏览 → 上传 → 下载 → 确认删除；拒绝计划不会发写请求；重新打开页面能恢复任务显示；10 万对象数据集的分页和虚拟滚动不阻塞界面，排序/搜索范围标注准确；两种语言和主题逐页走查。

**交付：**可日常使用的 R2 桌面主流程、界面和交互验证记录。

## 8. Phase 4：预览、分享、图床与用量

**目标：**补齐首版使用体验，继续复用已有的读取与传输用例。

- [ ] 预览图片、音视频、PDF、文本/代码/JSON；有大小限制，音视频按范围读取。
- [ ] 验证 WebView 中的 R2 CORS 和短期链接访问，提供明确的设置说明，不自动开放桶权限。
- [ ] 分享默认 1 小时、最长 7 天的 R2 预签名链接；公开域名链接独立配置和展示。
- [ ] 目录上传返回对象链接清单，避免把目录当作可签名的单个对象。
- [ ] 图床提供剪贴板快捷上传、路径模板、可选压缩/WebP 和 Markdown 链接；明确临时链接的有效期。
- [ ] 用量按 prefix 与类型后台统计，可取消，保存扫描范围、统计时间和缓存。

**验收：**大视频无需完整下载即可播放；超限预览提示明确；自定义域名不会被错误用于 S3 预签名；小图在正常网络下从截图到链接的目标延迟为 3 秒，记录文件大小和实测环境；统计可取消且不阻塞界面。

**交付：**R2 预览、分享和图床流程，用量面板及相关使用说明。

## 9. Phase 5：MCP 与 Agent Skill

**目标：**让外部 agent 使用已经验证的 R2 用例，不再实现另一套操作引擎。

- [ ] 以 `bucky mcp` 提供 stdio 服务，复用连接、任务、只读规则和执行计划。
- [ ] 提供查询、读取、预签名、上传和计划/执行工具；工具及注解按实施时的官方规范核实。
- [ ] 非交互破坏性操作默认只返回计划；执行接受已生成的 plan ID，但 plan ID 本身不表示用户同意。逐客户端验证独立于模型参数的人工确认机制；无法可靠确认时只开放读取和计划，记录实际支持范围。
- [ ] 生成 Agent Skill；在核实客户端官方目录后提供项目级/全局安装，覆盖前先确认。
- [ ] 验证 GUI、CLI、MCP 的错误和写限制一致，输出与日志均无密钥和签名 URL 泄漏。

**验收：**通过外部 agent 完成“预览并确认移动 `backups/` 下 90 天前对象”的流程；将测试目录 `dist/` 上传到 R2，返回 7 天有效的逐对象链接或链接清单。只读连接拒绝写入，拒绝确认不执行计划，重复执行不会重复创建任务。

**交付：**MCP 工具、Skill、安装说明、两条 R2 演示流程。

## 11. 后续类型的固定接入步骤

每种类型沿用以下顺序，避免每接一家就重写架构：

1. 查官方 API、权限、endpoint、签名、分页、分片及校验限制，记录差异与支持范围。
2. 增加连接类型和配置校验；优先复用已有协议实现，独有协议新增适配器。
3. 通过统一对象契约与状态恢复测试，再补厂商专属验证。
4. 在真实服务完成浏览、上传、下载、计划执行和分享，记录未支持的能力。
5. 开放该类型的 GUI/CLI/MCP 入口，更新两种 README 和使用文档。
6. 单独增加生命周期、CDN、图片处理等增强功能，不让增强功能阻塞已验证的基础接入。

AWS S3 阶段补充 AWS profiles 导入及明确列出的凭证来源；不能仅因使用 AWS SDK 就声称支持所有 SSO/角色方式。OSS 阶段以原生 SDK 完成基础操作，CDN 刷新额外 SDK 与权限单独引入。

## 12. 功能扩展与排期

类型接入优先于扩大功能面。跨云复制和单向同步在至少两种类型稳定后单独规划；不同厂商的 ETag 不能直接作为内容相等依据，流量费用只能作有条件的估算。

安全体检、内置自然语言操作、PicGo/编辑器生态、自动更新、包管理器分发和 v1.0 挂载保留为后续方向。它们不占用 v0.1 的验收，不要求提前引入模型 SDK、文件系统驱动或同步引擎。

不承诺固定发布日期。每个阶段按验收结果推进；真实 R2 测试账号、桶级凭证和目标平台环境是验证前置条件，缺失时明确标为未验证，不能以本地兼容测试替代。
